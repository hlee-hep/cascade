Plugin ABI and Development Guide

ABI Versioning Policy
- Bump `CASCADE_PLUGIN_ABI_VERSION` when you change any ABI-visible surface (class layout, virtuals, or signatures).
- Do not bump for internal-only changes that do not affect plugin headers or binary compatibility.
- If an old plugin can fail to load, link, or run with a new `libCascade`, bump the ABI.
The runtime ABI version is available as `cascade.__abi_version__` in Python.

Required ABI Entry Points
Plugins must export two C symbols:

```cpp
#include "PluginABI.hh"
#include "MyModule.hh"

CASCADE_PLUGIN_EXPORT_ABI
CASCADE_PLUGIN_EXPORT void CascadeRegisterPlugin() { CASCADE_REGISTER_MODULE(MyModule); }
```

Build Requirements
- Compile against the headers from the target Cascade installation.
- Link against the same `libCascade` you will run with.
- Avoid inline/template-heavy APIs across the plugin boundary.
- Define `CASCADE_PLUGIN_NO_AUTO_REGISTER` so plugins only register via `CascadeRegisterPlugin()`.
- Use `${PREFIX}/share/cascade/scripts/plugin_sconstruct` as the supported plugin package template.

Plugin Project Layout
- `include/` for module headers (`*.hh`)
- `src/` for module sources (`*.cc`)
- `python/` for Python plugins (`*_module.py`)
- `build/` is generated by SCons

Template Usage
1) Copy `${PREFIX}/share/cascade/scripts/plugin_sconstruct` into your plugin repo as `SConstruct`.
2) Ensure your modules follow the layout above.
3) Build with `scons` and install with `scons install`.

Recommended Environment Variables
- `CASCADE_PREFIX` (Cascade install root)
- `CASCADE_CORE_INCLUDE` (defaults to `${CASCADE_PREFIX}/include/cascade`)
- `CASCADE_CORE_LIB` (defaults to `${CASCADE_PREFIX}/lib`)
- `CASCADE_PLUGIN_DIR` (defaults to `${CASCADE_PREFIX}/lib/cascade/plugin`)
- `CASCADE_PYPLUGIN_DIR` (defaults to `${CASCADE_PREFIX}/lib/cascade/pyplugin`)

Distribution
- Distribute the built `.so` together with the ABI version used.
- Rebuild plugins if the ABI version changes.

Suffix Filters
- C++ plugins: only `*Module.so` are loaded.
- Python plugins: only modules ending in `module.py` are considered.

Signature Verification
- Place an Ed25519 public key at `plugin_pubkey.pem` in each plugin directory.
- Each plugin directory must contain `plugin_manifest.json` and `plugin_manifest.json.sig`.
- The manifest signature is verified once, then each listed module file is checked against its manifest SHA-256.
- Files not listed in the signed manifest are ignored.
- If the key, manifest, signature, or file hash is invalid, the affected plugin directory or module is skipped.
Unsigned Python plugins are not accepted by the Cascade controller: discovery skips them, and `py_amcm.register_module(...)` only resolves Python modules imported from verified `cascade.pyplugin` manifest entries.

Runtime Module Management
- Use `py_amcm.register_module(...)` for both C++ and Python plugin modules.
- The controller resolves C++ modules from the C++ registry and Python modules from verified `cascade.pyplugin` manifest entries.
- Direct inline Python module registration is disabled; Python analysis modules must be installed as signed plugins.

Duplicate Name Policy
- Module names must be globally unique across installed C++ and Python plugins.
- Duplicate C++ registrations fail during plugin registration.
- Duplicate Python module names in manifests fail during Python plugin indexing.
- A name exposed by both C++ and Python plugins is treated as an error; `py_amcm.register_module(...)` refuses ambiguous resolution.
- Use `cascade doctor plugins` to detect duplicate names before runtime.

Build Checklist (C++ plugins)
- Compile with `-DCASCADE_PLUGIN_NO_AUTO_REGISTER`.
- Export `CascadePluginAbiVersion()` and `CascadePluginAbiTag()` via `CASCADE_PLUGIN_EXPORT_ABI`.
- Provide `CascadeRegisterPlugin()` and register modules there.
- Name the library `lib<YourName>Module.so`.
- Include the `.so` in `plugin_manifest.json`.

Build Checklist (Python plugins)
- Name the file `<name>_module.py`.
- Place it in `${CASCADE_PYPLUGIN_DIR}`.
- Include the `.py` file in `plugin_manifest.json`.

Signing Helper
Use `scripts/sign_plugin.sh` to sign a manifest payload:

```bash
./scripts/sign_plugin.sh /path/to/plugin_manifest.json /path/to/private_key.pem
```

Examples

Generate a keypair (Ed25519):

```bash
openssl genpkey -algorithm ED25519 -out plugin_private.pem
openssl pkey -in plugin_private.pem -pubout -out plugin_pubkey.pem
```

Sign a C++ plugin manifest and verify loading:

```bash
cp plugin_pubkey.pem /home/$USER/.local/lib/cascade/plugin/plugin_pubkey.pem
./scripts/sign_plugin.sh /home/$USER/.local/lib/cascade/plugin/plugin_manifest.json plugin_private.pem
```

Sign a Python plugin manifest:

```bash
cp plugin_pubkey.pem /home/$USER/.local/lib/cascade/pyplugin/plugin_pubkey.pem
./scripts/sign_plugin.sh /home/$USER/.local/lib/cascade/pyplugin/plugin_manifest.json plugin_private.pem
```

Doctor Command
Use the CLI doctor to verify the installed plugin package:

```bash
cascade doctor plugins
```

Useful options:

```bash
cascade doctor plugins --cpp-dir /path/to/plugin --py-dir /path/to/pyplugin
cascade doctor plugins --no-abi
```

The doctor checks public keys, manifest signatures, listed file hashes, unlisted stale files, Python module classes, and C++ ABI version when possible.
